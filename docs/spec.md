# 竹東與台北雙向轉乘攻略規格

## 目標

提供家庭成員一個手機優先的固定路線看板，整合當日低班次、多段轉乘資訊，快速判斷下一組可搭行程。

## 主看板

依序提供「國光客運」「台鐵」「高鐵」三個分頁。每頁預設顯示最近三組，並可展開今日全部；台鐵預設顯示前往台北的行程，榮華直達新竹與竹中轉乘組合依第一段發車時間一起排序，同時發車時以轉乘較少者優先。

首頁三個交通分頁皆提供「顯示已過組合」篩選，預設關閉。開啟後，列出今日所有符合路線與轉乘規則的行程，並自動展開今日全部。第一段已發車的行程顯示灰色「已過」標籤；尚未發車者顯示「即將到來」及發車倒數。當剩餘時間少於出發準備時間時，行程不會隱藏，但「即將到來」改為黃色 warning 標籤。

每張卡片顯示剩餘時間、各段起訖站、發車與抵達時間、車次、轉乘站、轉乘間隔、最終目的地、抵達時間及總時數。榮華直達新竹的班次標示「直達新竹」。六家至高鐵新竹的步行不顯示為獨立搭乘段，也不另計一次轉乘；改在六家抵達段標示「步行至高鐵新竹轉乘」及抵達六家至高鐵發車的完整間隔。

## 時間規則

- 出發準備：榮華 25 分鐘、朝陽路口 15 分鐘。剩餘時間少於此門檻時保留行程，並以黃色「即將到來」標籤提醒。
- 最短轉乘：竹中 5 分鐘、六家步行至高鐵新竹 10 分鐘、新竹站內 5 分鐘。台鐵行程的每次轉乘間隔須小於 20 分鐘。
- 高鐵行程於竹中的轉乘間隔最少 5 分鐘且須小於 20 分鐘；六家抵達至高鐵發車的完整間隔最少 10 分鐘且須小於 40 分鐘，並包含步行時間。
- 主看板及班次查詢只處理今天。

## 台鐵、高鐵固定班表

只提供新竹至台北的台鐵與高鐵班次，不讀取或呈現 5608、9003 資料。

台鐵與高鐵使用頁面上方的 sticky Tab 切換，預設隱藏已發車的班次，可用「顯示已過班次」重新顯示。班次狀態每分鐘依目前時間更新；未顯示已過班次時，發車後會自動隱藏，顯示時則會改標為「已過班次」。

「對號列車」只套用新竹至台北的台鐵路段，在主看板與台鐵班表共用裝置偏好，預設開啟。

台鐵主看板提供「直達新竹」篩選，預設關閉；開啟後只顯示第一段由榮華直達新竹、不需在竹中換車的組合。

台鐵主看板另提供「僅前往新竹」篩選，預設關閉並記住裝置偏好。開啟後，行程終點改為新竹，列出榮華直達新竹及「榮華 → 竹中 → 新竹」的全部可搭組合，不接續新竹至台北班次；出發準備時間及竹中轉乘規則維持不變。此模式不套用新竹至台北的「對號列車」條件，但保留「直達新竹」篩選；兩者同時開啟時，只顯示榮華直達新竹的組合。

## 資料與安全

GitHub Actions 每日台灣時間 04:30 使用 Secrets 中的 TDX Client ID／Secret 取得資料，產生不含憑證的 JSON 並提交儲存庫。網頁不直接呼叫 TDX。手動更新由有寫入權限者在 Actions 執行，每日最多兩次且不可並行。

「僅前往新竹」使用每日資料中既有的榮華至新竹及榮華、竹中、新竹分段班次，不增加 TDX API 呼叫。

資料過期或離線時保留舊班表並顯示醒目警語、資料日期與最後更新時間；舊資料停用即時倒數。頁尾標示 TDX 資料來源及以官方營運資訊為準。

## 發布

以 Vite、TypeScript 與原生 HTML/CSS 建置 GitHub Pages。網站公開、不含個人資料，支援深色模式、PWA 安裝及最後班表離線存取。

## 台北往竹東

首頁 H1 顯示「竹東 → 台北轉乘攻略」與可點擊的雙向箭頭圖示。點選標題或圖示即切換為「台北 → 竹東轉乘攻略」，再次點選切回，並記住裝置偏好。沿用交通分頁、行程卡、顯示已過組合與最近三組／全部操作。

- 客運：台北轉運站 → 朝陽路口，使用 1820／1820A 實際反向班表。
- 台鐵：台北車站 → 新竹 → 榮華，或新竹 → 竹中 → 榮華；新竹、竹中轉乘皆至少 5 分鐘、未滿 20 分鐘。
- 高鐵：台北車站 → 高鐵新竹 → 步行至六家 → 竹中 → 榮華。高鐵新竹抵達至六家發車至少 10 分鐘、未滿 40 分鐘，包含步行；竹中轉乘至少 5 分鐘、未滿 20 分鐘。
- 反向「對號列車」套用台北至新竹的台鐵段；「直達榮華」保留新竹直達榮華的組合；「僅抵達新竹」將終點改為新竹，仍從台北出發並保留「對號列車」篩選，不接續往榮華，此時隱藏並暫停套用「直達榮華」。後兩項按方向分別記住偏好。
- 準備時間沿用客運 15 分鐘、鐵路 25 分鐘，僅作為提醒，不隱藏尚未發車行程。
- 固定班表隨方向改為台北至新竹；固定班表 H1 維持一般標題，下方以 H2「新竹 → 台北／台北 → 新竹」取代查詢說明，點擊 H2 或雙向箭頭可直接切換方向，保留目前交通分頁及篩選，返回首頁仍保留方向。

資料產生程序新增六組反向鐵路 OD 查詢；客運共用原本的回應，依站序取出反向車班。反向時間不由去程推算。舊 JSON 未含反向資料時顯示等待資料更新，不補造班次。搜尋僅使用各交通方式指定方向的固定路段，避免往返繞路。
